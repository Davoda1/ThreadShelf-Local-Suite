# ThreadShelf Local Suite 1.4.0 verification record

## Scope

Reader and Alternative add speech playback with bundled Pocket TTS and Kokoro CPU engines, configurable providers, streamed or buffered playback, per-message controls and an audio cache. Analytics receives only the coordinated application version update. Existing application profiles, archive/schema identifiers and Electron 45.1.0, Node.js 24.22.1, managed npm 12.2.1 and ONNX Runtime 1.31.1 pins are retained.

The speech asset manifests pin download URLs, sizes and SHA-256 digests. Build-time preparation verifies downloaded archives and retained support files, creates a complete platform inventory, and packages only the common payload plus the selected native platform. Package staging rejects missing, changed or unexpected asset files. Runtime model downloads are not used. Original notices, model/voice attribution and corresponding GPL source archives accompany the speech payload.

The cache policy selects a valid pinned recording first, then an API recording when the preference is enabled, then an exact settings match. Cross-settings reuse binds a full-message fingerprint to both the source and message identities, preserving the original code/citation selection. Exact synthesis matches remain reusable when spoken text and generation settings are unchanged. Older entries require a stored spoken-text identity or reconstruction of a proven synthesis identity rather than source/message IDs alone. Availability indicators and playback use the same selection function. Disabling the disk cache prevents disk audio lookup and playback while retaining eligible temporary audio. Cached playback reports the recording's original provider, model and voice. Tests cover provider/voice changes, identity isolation, expiry, corruption, restart, read-only availability and preference changes. Regenerated temporary audio cannot inherit a pin from different stored bytes, and restored pinned disk audio replaces a different temporary copy. Pinned originals remain protected from replacement even when their files are missing or corrupt; a new completed recording can be saved under a separate storage key. Eligibility is rechecked after asynchronous validation so a concurrent unpin or deletion cannot leave stale availability.

Source review retained the existing trusted-main-frame IPC checks and explicit command allowlists. Provider URLs, key headers, request/audio sizes, credential encryption, cache deletion previews, active/pinned protections and source-scoped cache identities remain bounded. Two readable historical source metadata files now use relative preparation paths; their original proof hashes remain bound to the unchanged 1.3.0 metadata companion via the manifest's existing `metadata` storage location. Historical archive identities and validation evidence are not rewritten.

## Required native release gates

The release workflow builds all three applications for native Windows and Linux runners. Each Reader and Alternative job must execute the packaged CPU module and bundled workers for buffered speech, streaming, cancellation and temporary-file cleanup. Its generated speech report is required by release assembly in addition to the existing package, runtime, graphical application and publication-ledger evidence. Missing or failed speech evidence prevents publication.

All nine native packages remain required even though Analytics behaviour is unchanged. The release also contains two synthetic HTML previews, exact tagged suite source ZIP/TAR.GZ, the refreshed offline manual ZIP, verification report/evidence ZIP and one SHA256SUM.txt manifest.

## Limits

This source review does not assert that a GitHub workflow has run or that a release has been published. The final release report must identify the exact tagged commit, successful native jobs and asset digests. Native Windows execution, system-wide DEB installation, every operating-system variant and real remote-provider accounts require their own evidence; they are not implied by local source tests. Offline CPU tests use synthetic text, and remote provider availability is independent of the bundled engines.
