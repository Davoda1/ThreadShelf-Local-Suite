# Explorer definitions 19–32

`src/core/explorer-b.mjs` calculates these measurements independently of the legacy 1.0 tables. The algorithm identifier is `2.0.0-b1`. Legacy filtered-order `modelChanges`, legacy usage interpretation, and legacy depth definitions retain their existing identifiers and numerical meanings.

The input is the applied `applyFilters` selection and immutable normalized source conversations from Analytics-owned captures. Each chart returns scalar exact rows, declared column keys, display coordinates, and a measurement contract. The contract identifies the variable, unit, population, available/unavailable counts, filter scope, date basis/timezone/precision, branch policy, perspective, representation, reliability, algorithm, and evidence rule. A table row carries an opaque `evidenceKey`; IDs stay in the worker-owned evidence map. Evidence queries use scoped IDs and paginated original-source resolution. Quantile rows share a lazy resolver rather than copying archive-wide ID arrays repeatedly.

## Full-text index validation

New code-point calculations trust only `explorerAnalysis` with the current `EXPLORER_TEXT_ALGORITHM_VERSION`. Storage validates that index against the index schema and base snapshot fingerprint before use. Unindexed complete source text can be independently scanned. An excerpt cannot substitute for full text, and legacy `contentAnalysis` is never a shortcut for a new metric.

The prompt-key helper has independent Node `crypto` oracle checks for empty strings, Unicode/NFC, null bytes, case sensitivity, multi-block input, and SHA-256 padding boundaries. It is synchronous and browser-compatible; it sends no wording to another process or service.

## Comparison and history controls

`buildExplorerB(selected, options)` accepts `originalConversations`, `comparisonA`, `comparisonB`, `sequenceConversationId`, chart-specific `chartControls`, optional `usageAudits`, and optional `history`. `history` accepts immutable `previousCapture`/`currentCapture` objects or `{enabled:true,diff}` from the history service. The UI/export layer controls applied selections and preserves full table rows while rendering a disclosed bounded plot subset. Snapshot and capture dates are provenance, not activity dates.

The metadata-only service diff route accepts only `capture-diff:1`, an actual left/right capture descriptor, and nonnegative exact summary counts. It retains producer metadata and optional path/capability changes without transferring conversation text or private source paths into chart rows.

## Verification scope

`test/explorer-b.test.mjs` uses meaningful synthetic fixtures with independently expected graph depths, filtered adjacency, distinct calls/outputs, ambiguity, zero/unknown timing, same-task concurrency, audited token-field pairing, supplied context limits, aligned totals, weighted quantiles, exact content intersections, reconciliation, observability, diagnostics, immutable history diffs, and stale/excerpt index rejection. These are engine tests, not claims of universal real-provider metadata completeness. Real export metadata can legitimately leave a functional engine unavailable when required fields or verified semantics are absent.
